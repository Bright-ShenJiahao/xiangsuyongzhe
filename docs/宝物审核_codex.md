# 宝物重设计审核 · Codex

审核依据为 docs/宝物重设计.md、当前 js/data.js、js/battle.js 与 js/camp.js。本文只给设计和实现建议。本次没有接入新版宝物或突破机制，以下数值是首轮候选，尚无平衡实测结论。

## 1. 数值与明显优势组合

### 1.1 起手 dmg 百分比伤害

按草案的未加成起手伤害计算，荆棘为剑9、枪10.5、弓6、杖13.5，Lv5翻倍。剑系圣光斩为12～24，枪系龙息为8.4，法杖击杀爆炸为9。若仅怪物血量从×1升到×2.1、其他因素不变，同一固定伤害的相对血量占比降为约47.6%。所以主要风险是早期过强、后期成长不足，同时按“命中次数”触发的多段流能将固定伤害大量放大。实际还需计入怪物种类、护甲、精英血量和玩家成长，不能据此判定最终击杀能力。

建议统一定义 B_w 为对应兵器起手技能的 DATA.skills[w].dmg，固定读取对应系，避免换起手武器影响跨系宝物。附加伤害可吃该系属性与装备伤害倍率及敌方减伤，不吃本宝物或其他宝物触发加成，不暴击、不叠熟练度、不再次触发宝物。若坚持草案“完全不吃成长”，则应接受后期用途衰减，而不能承诺跨六章强度稳定。

| 宝物 | 建议 Lv1 → Lv5 | 触发限制 |
|---|---|---|
| 荆棘护符 | 100%×m B_w，范围40像素格 | 实际损血后触发，同一玩家1秒一次，持续伤害可触发但共享冷却，无敌/闪避不触发 |
| 圣剑碎片 | 120%×m B_sword，范围45像素格 | 每5次剑系施放触发一次，单次施放最多计1次，附加斩不计数 |
| 龙骑士枪柄 | 枪系施放首次击杀时20%概率喷息，伤害100%×m B_spear | 每次施放最多1次，全局1秒冷却，不对每个死亡目标掷骰 |
| 魔力药瓶 | 法杖施放首次击杀时20%概率爆炸，伤害80%×m B_staff，范围30像素格 | 每次施放最多1次，全局1秒冷却，爆炸不触发击杀爆炸 |
| 磨亮的剑刃 | 物理剑系暴击后，额外剑气为该次实际命中伤害25%×m | 每次施放最多1道，全局0.8秒冷却，不使用整招总伤害，不递归 |

这些限制优先于继续降低伤害百分比。尤其圣剑碎片原“每第5次命中”可能被旋转、飞剑、多目标与持续判定迅速触发，必须规定计数单位。

### 1.2 建议调整的组合

- 长枪头破甲作用于所有伤害，会成为跨系通用增伤。建议6%×m易伤，持续2秒，同一目标只刷新、不叠层，与其他同名易伤取最大值。这里“破甲”实际不是扣防御，名称改为“枪痕”更准确。
- 皮护指建议每层3%×m，最多4层，合计12%～24%，持续2秒。以每次施放的主目标累计，穿透、散射的次目标不清空主目标计数，换主目标才清零。
- 贤者法典原持续时间+50%～100%会同时增强冰冻控制、吸附聚怪和灼烧伤害。建议灼烧持续+20%×m，冰冻/吸附持续+10%×m，状态目标伤害+5%×m。首领继续沿用既有控制抵抗规则，不能绕过。
- 红枪缨原满层为+45%～90%距离，容易变成范围必选。改为每层+5%×m，最多3层，共+15%～30%，只计一次施放，持续3秒。
- 四叶草建议保留12%×m概率，但每次施放最多掉1币、全局0.5秒冷却、每站最多8×m币。否则箭雨、旋风、召唤物反复判定会破坏经济。
- 守财奴建议 floor(coins/20)×1%×m，上限8%×m，160币达到上限。原文只放大cap时，Lv5需320币才满，必须明确意图。
- 完美主义建议10%×m，受伤后失效，恢复满血且维持0.5秒才恢复。与狂战士能同时携带，但不会同时满足满血与低血条件，草案“二选一”需要明确是设计偏好还是互斥规则，建议不增加硬互斥。
- 猎魔额外币建议精英4×m、小头目6×m，首领不适用，同一敌人只结算一次。原8～16币相对现有精英+5、小头目+8较高。
- 存钱罐与守财奴都奖励持币，属于协同，不是文中所说“互相拉扯”。拉扯发生在两者和商店消费之间。
- 钱袋在开局后拿到时不能只写“开局+30”，建议仅进本局第一次装备时发放30×m，合并只补新旧等级差额，不可通过反复装卸刷钱。这是待选择的经济改动。

## 2. 与装备、属性、誓约的重叠

草案大多数宝物通过触发条件获得独立身份，但效果产物仍有重叠。可以保留分工边界，无需让每个数值类型绝对互斥。

| 项目 | 重叠处 | 建议 |
|---|---|---|
| 锋刃油 | 疾风之誓和装备词条同为攻速 | 改为物理暴击后2秒获得6%×m攻速，刷新不叠，不减少固定动作到负值 |
| 剑鞘 | 攻速效果与疾风、第三招规则相近 | 保留“单次剑招命中≥3人”的识别度，奖励下一次剑系施放前摇减少15%×m，最低0.1秒，不能被同次招式消费 |
| 水晶棱镜 | 敏捷/智力和装备都提供暴击 | 保留触发式效果，下一次法杖施放暴击率+10%×m，消费一次，持续最多3秒 |
| 斗篷 | 轻羽步、残影步都有移动/闪避收益 | 闪避后移速+15%×m、1.5秒、全局2秒冷却，避免长期高速不可读 |
| 铁壁护符与赌注伤害宝物 | 直接改变数值，和“宝物不加纯数值”原则冲突 | 作为用户明确保留的赌注型例外，文档中明说，不另改装备 |
| 贤者法典、鹰羽箭袋 | 条件增伤和装备伤害有交集 | 用状态和距离建立行为差异，并明确每段伤害的距离来源 |
| 猎魔印记 | 屠龙之誓同样针对精英 | 经济与提示不回血，保留 |

便当从现有“每波”到新表“每站”是明显改动。若一站三波，6%×m从最多18%×m降为6%×m。建议明确采用每站8%×m，暂价34，站号与续关共享领取标记。草案“不叠加其它回血”有歧义，应改为可与其他来源分别结算，每次治疗统一经过healHero应用治疗倍率。不要仅为此新增回血互斥。

法力透镜“魔法暴击时这一招范围增大”有因果问题。当前范围决定命中对象，命中后才判暴击。建议魔法暴击后，下一次法杖施放范围+15%×m，持续最多3秒，消费一次。收益形式更接近誓约，但实现与玩家理解均更清楚。

## 3. 十二件兵器系覆盖逐项检查

| 系 | 第一件覆盖 | 第二件覆盖 | 第三件覆盖 | 结论 |
|---|---|---|---|---|
| 剑 | sword、whirl、guard、storm | wave、phantom、flash | holysword | 4+3+1=8，互斥完整 |
| 枪 | spear、javelin、hundred | sweep、drill | rising、leap、dragon | 3+2+3=8，互斥完整 |
| 弓 | bow、barrage、pierce | fan、homing、cyclone | rain、starfall | 3+3+2=8，互斥完整 |
| 法杖 | nova、chain、blizzard | staff、pillar、thunder | orbs、abyss | 3+3+2=8，互斥完整 |

32技能均覆盖一次，无跨件重复。但圣剑碎片只覆盖一个宗师技能、剑鞘覆盖四个技能，同样是钥匙时可用面和出现时机差异大。建议保留定价24/30/46作为初稿，圣剑碎片仅在已经拥有holysword或有宗师选书时进入定向商店池，普通随机池可有低权重，不能拿到前就被迫占格。

突破Lv8尚未定义。建议先定为继承Lv7效果、基础技能伤害再乘1.10，不重复放大投射物数量、范围、控制持续和召唤数量。需要覆盖全部升级入口、熟练度显示和移除钥匙的行为。推荐钥匙在升级时校验，突破后保留Lv8，宝物移除仅失去特色效果，避免技能降级与经验回滚。以上均为建议，不能从本次审核直接视为已实现。

## 4. 钩子与实现成本

hurt负责敌方受伤，damageHero负责玩家受伤，healHero统一治疗，kill集中敌人死亡，SKILLS管理技能的多段状态。不能把所有新规则都直接写在hurt上。

- 低成本：读取RUN.coins、满血条件、玩家真实损血、成功闪避、精英击杀和全局冷却。需确保死亡只记一次、减伤到0不算损血。
- 中成本：剑系暴击、法杖击杀等需要传入来源。给伤害事件保留skillId、castId、伤害来源种类、是否二次伤害，使用同一施放id穿过投射物和持续区域。
- 高成本：一次施放命中≥3人，需要Set去重与招式生命周期；持续伤害与召唤不能每帧清Set。“同目标连续命中”涉及目标身份与穿透次目标，建议采用第1节主目标规则。
- 高成本：箭矢飞行距离不是敌我当前距离，弹射、分裂需要定义是否继承累计距离。建议只让直线/追踪投射物按实际路程累计，箭雨等地面技能按施放点到落点距离判断，阈值统一使用像素格100，转换通过K。范围40/70等也需声明是像素格而非原图像素。
- 高成本：暴击后反向改变已完成的命中范围。采用第2节“下一次施放”替代。
- 高成本：灼烧、冰冻、吸附延长，需要每种状态的创建入口；不能只延长特效动画时间。首版可只做灼烧延长20%×m，保留后两种待接入。
- 必须统一：所有附加伤害源不递归触发宝物，不能重复给技能熟练度。同一招多次tick不会重复消费“下一招”奖励。

建议先接低成本生存与经济钩子，再做带castId的兵器系。文档声称“只改DATA.startItems”和“需要一并接Lv8”互相矛盾，实际落地必然涉及技能、伤害管线、界面和存档迁移，需另列实现任务。

## 5. 赌注叠加与封顶

Lv5王冠+30%、玻璃剑+40%、低血项链+40%。若加算，三者合计+110%，即2.10倍；若各自乘算则1.3×1.4×1.4=2.548倍。原文未定义，应明确同类宝物伤害先加算。

王冠与贪婪各+15%承伤，铁壁Lv5−20%。加算为1.10倍承伤，独立乘算为1.15×1.15×0.8≈1.058倍。代价可以被铁壁部分抵消，但会花第三个宝物格。

建议首轮采用以下规则，仅约束宝物贡献，不给装备、属性、誓约施加新总封顶。

- 同类增伤宝物加算，上限+80%，再与其他系统按既有公式合并。含满血、低血、持币及赌注类通用增伤，距离/状态条件也需写明是否进入同桶。
- 宝物减伤上限20%，承伤增加累加，再计算clamp(1+增伤代价−宝物减伤,0.8,2)，随后走既有防御等流程，避免负伤害与无敌。
- 玻璃剑的−20%生命、王冠/贪婪的+15%承伤、项链的−30%治疗、铁壁的−10%移速均固定，不随m放大。合并提升收益，玩家提前知晓固定代价。
- 最大生命最终至少1。治疗倍率最低0。统一通过healHero覆盖肉、篝火、波间回血、屠龙与其他来源。
- 80%封顶是首轮安全候选，需显示溢出，否则玩家会误以为合并仍有完整收益。也可先降低单件收益替代总封顶，避免隐藏收益损失。

## 6. 存档兼容与迁移

旧版30件，新版删除4件、新增4件，仍为30件。17个效果变更id（clover、cloak、blade_oil、mana_lens、heavy_armor及12件兵器系）可保留，但描述、图鉴、商店预览与构筑计算必须同版切换。旧记录自动采用新规则属于玩法变化，应提示一次版本更新。

建议给快照增加显式迁移版本，以纯数据迁移后再recompute。需要遍历RUN.gear、RUN.bag、已生成商店库存、结算待选物品以及局外起手选择，不能只清理已装备格。旧快照不一定有这些字段，按存在性处理。

删除宝物退款建议原价乘等级，按Lv1～5的累计同名件数1～5计算，例如护身符Lv3退26×3=78币；若用户坚持每格只退原价，应明确这会忽略合并投入。退款后清空该格，不压缩背包索引，输出一个合计提示。

迁移必须先在副本上完成，写回同一存档，持久化成功后才发提示。退款与版本标记同时写回，重载不重复退款；写入失败不改原存档并报告失败。每个用户存档槽分别迁移，不能只迁移当前槽的内存。物品id缺失时输出可诊断记录，不静默删除未知物。

新增宝物在新掉落池生成；旧商店库存建议迁移时仅过滤删除id并填补，不能把已经购买的商品复活。熟练度、附魔、技能格、宝物等级、誓约等级、铜钱、水晶、称号和彩蛋原样保存，临时冷却/命中计数默认重置，避免持久化敌人引用。

现有RUN以JSON整对象保存再Object.assign恢复，仍需单独验证多槽、死亡续命、旧版本缺字段与删除id退款。本次存档查漏报告是当前旧宝物版本的单次往返结果，不能证明未来新版迁移正确。
