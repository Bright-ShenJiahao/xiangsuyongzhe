# 新增英雄动作帧接入指南

新增角色时，只处理该角色。阿远用于观察游戏中的人物比例和像素风格，各角色可以保留自己的头高、饰物和原有配色。

1. **保存源图和切帧映射。** 收齐剑、枪、弓、法杖、圣典、掌机、镰刀与头像，登记武器、动作、帧序和源文件路径。每帧按内容取边界，留出长武器所需空间。先核对完整的人物、手、武器尖端和细线，再打包。动作复用要明确列出，不能留空白帧。
2. **抠图先保轮廓。** 从原始精灵表裁剪，预览浅底和深底。确认是真背景才删 alpha，粉边优先只改轮廓 RGB。不要按整帧色阈值删紫色或浅色，也不要用描边盖住缺口。若武器或人物已有缺口，回到原图补回像素；图集里没有的细节不能通过重新描边恢复。
3. **尺寸先固定再抽查。** 先用该角色的剑待机确定游戏内大小，以发顶或头盔本体到靴底估计人物高度，排除羽翎和武器。七武器优先用同一固定倍率、最近邻缩放。逐帧比对源图的头、肩、手和靴子，只有这些部位一起变大或变小才单独修正；蹲伏、出招、翻滚、腾空保留本来的姿势变化。不要把整张帧缩放到统一外框高。
4. **落脚和横向重心独立校准。** 接地帧的 ay 取支撑靴底，确认贴线的是靴子而不是刀尖、枪杆、披风或弓身。跳跃、腾空后撤、翻滚、倒地沿用动作的锚点逻辑。ax 以头和躯干为参照，不按带武器的图框求中心；原画有重心移动时保留动作意图。按跑步循环和前摇、出手、收招顺序复核，单张站得住还要连播不抽动。
5. **打包和接入。** 参考当下 preview 的角色配置。图集放 art/hero<角色>/atlas.png 和 atlas.json，头像放 art/portrait/<id>.webp。检查 js/data.js 角色注册、js/sprites.js 图集加载与动作回退、js/ui.js 选人和存档恢复、demo/intro.html 高塔、demo/palace.html 宫殿、tools/frames.html 帧校准页，以及 iframe 的 h= 传递。原始帧数和游戏动作映射不是一回事，按实际动作键核对。
6. **验收后推 preview。** 先查全部帧越界、空白、动作映射与尺寸变化，再将异常及每系待机、跑步和攻击放进一张对比图。用脚底线检查落脚，轮廓有疑问的帧逐一对照原图。基础试跑选人、开场、宫殿和短时战斗，覆盖 PC 和手机竖屏。记录已查的部分和缺失素材，提交后只推 preview。脚本筛查结果和肉眼看过的范围分别报告。

目前的 tools/pixel/fix_all_heroes.py 是六位旧角色针对历史提交的修复脚本，依赖指定 Git 基线。新角色应从它自己的源图和动作映射生成图集。

### 待机呼吸不能按整帧底部定位
女骑士的法杖尾和阿远镰刀柄尾会低于靴子，不能取整帧最低alpha像素作为ay。待机两帧要对比同姿势的靴子和躯干，保留上身正常呼吸下沉，让支撑脚贴在同一条地线上。已人工核对的待机修正见tools/pixel/hero_idle_anchor_overrides.json；图集重建前后都应检查这些标记的图块矩形，不能只检查空白/越界就宣称不抖动。
